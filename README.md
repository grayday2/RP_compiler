# RP2040 Portable Compiler — пробный комплект

Портативная Windows x64-среда сборки для совместимых плат **RP2040-Zero**.
Исходники прошивки HID Binder находятся в `main.cpp` в корне.
Arduino IDE, установленный Python, Git и права администратора не нужны.

## Скачать и запустить

**Готовый лёгкий архив: [`packages/RP2040_Portable.zip`](packages/RP2040_Portable.zip).**
Он содержит исходники, библиотеки и установщик, но не сотни мегабайт инструментов.
GitHub Release не создаётся. При скачивании ZIP через GitHub используйте
кнопку Download raw file, а не сохраняйте HTML-страницу просмотра.

1. Распакуйте ZIP в **НОВУЮ папку**, например `C:\RP2040_Test`.
   Не накладывайте на вашу рабочую копию. Резервную копию оставьте отдельно.
2. Запустите **`first_setup.cmd`**. Нужен интернет и несколько гигабайт свободного
   места для архивов, временной распаковки и готовых инструментов.
3. Дождитесь **SETUP COMPLETE**. Полный лог — `debug/logs/setup.log`.
   На завершающий вопрос: **Enter** — закончить и оставить кэш;
   **y + Enter** — удалить скачанные архивы и временную распаковку.
   Установленные инструменты и прошивка остаются на месте.
4. Запустите **`compile.bat`**. Сборка больше не требует интернета.
5. При **SUCCESS** получите `output/firmware.uf2`; лог — `debug/logs/build.log`.
6. Зажмите BOOT, подключите плату, отпустите BOOT и скопируйте UF2 на `RPI-RP2`.
   Установщик и сборщик никогда не прошивают плату автоматически.

Для первого теста используйте короткий путь без кириллицы и спецсимволов.
Пути заключены в кавычки, но поддержка необычных имён зависит также от Make/GCC.
Установка и сборка прошли проверку на Windows-runner с PowerShell 5.1.
Это экспериментальный комплект: аппаратная проверка новой связки предстоит.

## Первичная установка

Точка входа — `first_setup.cmd`; он вызывает `first_setup.ps1` через встроенный
Windows PowerShell 5.1 с `-NoProfile -ExecutionPolicy Bypass` **только для этого
процесса**. Постоянная политика Windows, реестр и системный PATH не меняются.
Доменная политика может запретить запуск независимо от Bypass.

Можно запустить PS1 непосредственно:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\first_setup.ps1
```

`dependencies.lock.json` фиксирует версии, URL и SHA-256 **скачиваемых файлов**.
Никаких master/latest, поиска случайного компилятора в PATH или отключения TLS.

| Компонент | Зафиксированный вариант |
|---|---|
| CMake | 3.30.5, официальный Windows x64 ZIP |
| ARM GCC | **xPack 13.3.1-1.1**, GCC 13.3.1, Windows x64 |
| GNU Make | **mbuilov 4.4.1 x64**, commit `2a2989816aece7c191c0015bff30d104ef31f52a` |
| Python | 3.10.11 embeddable x64, официальный ZIP python.org |
| Pico SDK | 2.3.0, commit `98a542c1a62fb549ffb5d66a3e5892b06276b670` |
| TinyUSB | commit **`aa410008e8e74b0727f8c30a1ec109ff2c37efc6`**, объявляет 0.21.0 |

**Это новая воспроизводимая связка, не побайтная копия старого окружения.**
Make выбран заново; xPack — другая упаковка/сборка ARM GCC. У TinyUSB два
заголовка и время commit совпали с рабочей копией, всё дерево ранее не сверялось.
Ничего из неизвестного исторического окружения установщику не требуется.

### Повторная установка, ошибки сети и офлайн

- Архивы остаются в `.setup-cache/`; их можно перенести на другой компьютер.
- Повторный запуск пропускает установленные компоненты с подходящими метками
  и хешами контрольных файлов. Это не полная проверка каждого файла установки.
- Чужие/изменённые непустые каталоги **не перезаписываются**. Для старой рабочей
  копии создайте новую папку, а не удаляйте старую ради установщика.
- ZIP проверяется до распаковки; неполная распаковка не публикуется в целевой
  каталог. Последующие компоненты можно доустановить повторным запуском.
- При ошибке хеша остановитесь: файл повреждён или источник изменился.
  Не удаляйте проверку SHA-256. Удалить можно только ошибочный файл из кэша.
- Если автоматическая загрузка заблокирована, скачайте точный URL из lock-файла
  браузером и положите файл в `.setup-cache/` под именем `archive` из lock-файла.
  Загрузчик проверит тот же SHA-256.

```powershell
# Установка только из заранее заполненного кэша:
.\first_setup.ps1 -Offline
# Проверка установленной связки, без скачивания и установки:
.\first_setup.ps1 -ValidateOnly
```

## Структура и замена

```text
RP2040_Portable/
├── first_setup.cmd / first_setup.ps1  # одна точка первичной установки
├── dependencies.lock.json            # фиксированные источники и хеши
├── compile.bat                       # обычная офлайн-сборка
├── main.cpp                          # редактировать прошивку здесь
├── CMakeLists.txt / pico_sdk_import.cmake / tusb_config.h
├── uf2conv.py
├── cmake/                            # внешний компонент целиком
├── toolchain/                        # внешний компонент целиком, включая Make
├── python/                           # внешний компонент целиком
├── pico-sdk/                         # SDK вместе с lib/tinyusb/
├── libraries/
│   ├── ru_keys/ru_keys.h              # единственная копия
│   ├── ssd1306/                      # драйвер и шрифт владельца
│   └── added_libs.txt
├── scripts/                          # механика сборки/установки и lib_installer.cpp
├── debug/                            # диагностика, README, logs/ и reports/
├── tests/                            # проверки без платы
├── docs/                             # история аудита и ограничения
├── tmp/                              # для добавления библиотек
├── build/                            # пересоздаётся при каждой сборке
└── output/firmware.uf2
```

Для переноса установленной среды копируйте все четыре внешние папки целиком,
включая скрытые `.rp2040-component.json`. Новые исходники не должны автоматически
обновлять инструменты. В Git инструменты, кэши, отчёты и прошивки не включены.

## Оформление и служебные файлы

Сборщик показывает шапку и шесть разделённых этапов. Успешные операции выделены
зелёным, ошибки — красным, если консоль поддерживает цвет. При перенаправлении
вывода цвета выключаются. `debug/logs/build.log` всегда остаётся обычным UTF-8
текстом; длинные команды сохраняются туда, не загромождая экран.

Диагностика и логи собраны в `debug/` с [описанием](debug/README.md).
Содержимое `scripts/` описано в [scripts/README.md](scripts/README.md): папка
по-прежнему необходима для сборки. Main, SDK, библиотеки и версии инструментов
при этой уборке не изменялись. Отдельного пользовательского архива нет:
обновляется прежний `packages/RP2040_Portable.zip`.

Очистка после установки удаляет только `.setup-cache/` и `.setup-work/`.
Отсутствующие папки пропускаются; при ссылках/junction очистка отказывается
следовать по ним. Если очистка не удалась, успешная установка остаётся успешной,
а предупреждение записывается в лог. Для автоматизации:

```powershell
.\first_setup.ps1 -NoPrompt               # без вопроса, сохранить кэш
.\first_setup.ps1 -NoPrompt -CleanupCache # без вопроса, удалить кэш после успеха
```

`-ValidateOnly` не задаёт вопрос и не удаляет кэш. `first_setup.cmd` после
успеха больше не показывает второе «нажмите любую клавишу»; при ошибке окно
остаётся открытым для чтения сообщения.

## Что изменено в пробной версии

- Установщик с проверкой хешей, кэшем, журналом и отказом от перезаписи старой среды.
- Сборщик использует только локальные программы, очищает CMake-кэш, фиксирует
  SDK/toolchain, удаляет влияние унаследованных PICO/CMAKE-переменных.
- Реальный `debug/logs/build.log`, проверка кодов возврата. Новый UF2 публикуется только
  после успешной сборки и конвертации. При ошибке прежний UF2 остаётся прежним —
  лог явно говорит, что новая прошивка не создана.
- Удалён корневой дубликат ru_keys.h; определения макросов предварительно сверены.
- Неэффективный `CHOSEN_GENERIC_03H` удалён. Явно выбран **boot2_w25q080** — та же
  реализация, которую выбирала проверенная конфигурация исходной сборки.
- Сохранено `PICO_FLASH_SIZE_BYTES=4194304` исходной рабочей конфигурации.
  Реальная ёмкость Flash двух плат с AliExpress не установлена; этот флаг её не
  измеряет. Для проектов, приближающихся к 2 МиБ, сначала определите память.
- Логика main.cpp, USB-дескрипторы, управление GP11 и OLED-драйвер не изменены.
- CMake допускает отдельную Linux-проверку через toolchain SDK; Windows-сборка
  остаётся основной. Автозагрузчик предназначен только для Windows x64.

`scripts/lib_installer.cpp` хранится как необязательный вспомогательный исходник. EXE в этот
архив не входит; для текущих библиотек он не нужен. Можно добавлять библиотеки
в libraries/ вручную. Ранее подготовленная версия установщика сохраняет подпапки
и не является доказанной копией исходника старого EXE владельца.

## Прошивка и безопасность тестирования

Группы CMD/SUPPORT/AUTH/KEYBOARD, OLED GP4/GP5, энкодер GP6/GP7/GP8.
Для русских макросов включайте русскую раскладку, для команд — US.
Тестируйте ввод сначала в пустом текстовом редакторе: CMD/AUTH могут выполнять
команды. Устройство не знает, какое окно имеет фокус. Не выбирайте неизвестный
макрос на рабочем компьютере.

Пароли в packed-массивах не зашифрованы. Перед публикацией собственных изменений
удаляйте реальные учётные данные; если опубликованные пароли действующие,
смените их. Установщик не читает пароли и не отправляет прошивку в сеть.

- `tests/test_setup.ps1` — офлайн-тесты установки на PowerShell 5.1 без Pester.
- `.github/workflows/portable-windows.yml` — проверка первичной установки,
  повторной офлайн-проверки и сборки на Windows в пути с пробелами.
- `debug/env_report.bat` и `debug/audit_working_copy.ps1` — отдельные средства диагностики.

Сведения о реально выполненных проверках — `docs/trial-validation.md`.
Аппаратных испытаний в агентской среде нет.

Работа с прошивкой (макросы, пароли, шрифт, проверка сканкодов):
`docs/firmware-authoring.md` + `scripts/audit_device.py`.
