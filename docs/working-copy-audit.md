# Завершающая проверка рабочей копии

Рабочая папка пользователя — эталон. Репозиторий — место изменений.
Не переносим main.cpp, не меняем SDK, TinyUSB и загрузчик ради реорганизации.

## Запуск

Скопируйте `debug/audit_working_copy.ps1` в папку `debug/` рабочей среды.
В PowerShell 5.1:

```powershell
& 'U:\RP2040_Portable\debug\audit_working_copy.ps1' -Root 'U:\RP2040_Portable'
```

Буква диска и имя папки произвольные. Нет зависимости от текущей рабочей папки,
если указан `-Root`. Execution Policy не меняется. При запрете PS1 можно
вставить содержимое скрипта в консоль, предварительно перейдя в корень проекта
(если запуск разрешён правилами вашего компьютера).

Результат: новый `rp2040_final_audit_*.txt` в debug/reports/. Старые отчёты не
перезаписываются. Разделы с `SECTION ERROR` неполны; сообщите об ошибке.

Скрипт не запускает сборку или EXE, не скачивает, не читает main.cpp, не меняет
исходники, не читает Git credentials/config. Хеширует готовые бинарники, но не
выводит их содержимое. В отчёт могут попасть локальные пути из правил сборки.
Проверка макросов ru_keys.h текстовая: не эквивалентна препроцессированию C.

Необязательно: `-FullEnvironmentHashes` добавляет SHA-256 всех файлов четырёх
внешних каталогов, без .git и ссылок. Это может занять несколько минут и создать
большой отчёт. Для первого запуска не нужно.

## Границы проверки

- Файлы зависимостей сборки могут подтвердить выбранный boot2 и ru_keys.h.
  Если их нет, скрипт не выдаёт предположение за факт.
- Хеши/макросы TinyUSB не доказывают точный commit всего дерева.
- Метаданные EXE, DLL и имена README помогают найти происхождение Make, но не
  доказывают его и не заменяют проверку импортов и запуск на чистой Windows.
- Ёмкость физической Flash и назначение GP11 не устанавливаются сканером ПК.
- Установщик нельзя перемещать без адаптации исходника и проверки нового EXE.

## Порядок дальнейшей работы

1. Сохранить резервную копию рабочей папки и текущий UF2 у пользователя.
2. Сопоставить этот отчёт с репозиторием; выбрать одну задачу.
3. Изменить только её, не обновляя инструменты параллельно.
4. Проверить тесты, Windows-сборку, затем нужное поведение на плате.
5. При неуспехе вернуть последнее изменение, а не накапливать обходные правки.

Скрипт подготовлен для Windows PowerShell 5.1. Его выполнение в агентской
Linux-среде не проверено: PowerShell здесь недоступен.
