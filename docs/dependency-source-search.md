Хеши вычислены по байтам `git show <commit>:<path>`, а не по тексту веб-страницы.
Совпадают без преобразования окончаний строк.

Это сильное свидетельство ZIP-снимка master на указанном commit, но не
доказательство идентичности всего дерева: соседние commits могут содержать те
же два заголовка, а дата могла быть сохранена при копировании/распаковке.

Кандидат на воспроизводимую загрузку:
https://github.com/hathach/tinyusb/archive/aa410008e8e74b0727f8c30a1ec109ff2c37efc6.zip

Это не проверенный архив: ZIP пока не скачан и его SHA-256 не установлен.
Для установки потребовалось бы содержимое верхнего каталога ZIP перенести в
`pico-sdk/lib/tinyusb/`. Сейчас ничего не устанавливаем и не перезаписываем.
Перед признанием точного восстановления нужно сравнить пути и SHA-256
остальных файлов (по крайней мере src/ и используемой части hw/).
Данные кандидата также сохранены в `tinyusb-candidate.json`.

## Make: точный источник пока не найден

Эталон пользователя:
- GNU Make 4.4.1, Built for Windows32;
- размер 331425 байт;
- дата файла 2023-03-02T18:20:55+03:00;
- SHA-256: cc6dc291113dcbcc7735835acbfc23c52ed037e4e124ff2d7a0aeae6df563a9f.

### mbuilov/gnumake-windows

https://github.com/mbuilov/gnumake-windows

На момент проверки HEAD: `2a2989816aece7c191c0015bff30d104ef31f52a`.
Проверены размеры **52 уникальных исторических EXE blobs** в доступной истории
репозитория (rev-list --objects --all + cat-file --batch-check).
Ни одного EXE размером 331425 байт не найдено. Текущий `gnumake-4.4.1.exe`
имеет 369664 байта; x64-вариант — 444928 байт.
Это исключает побайтное совпадение с проверенными файлами, но не стороннюю
пересборку из тех же исходников и не недоступные/удалённые варианты.

### maweil/CompileMakeForWindows

https://github.com/maweil/CompileMakeForWindows

GitHub API не вернул опубликованных releases при проверке.
`build_version.sha256sum` относится к исходному `make-4.4.1.tar.gz`, а не к
Windows EXE. Он не позволяет подтвердить происхождение файла пользователя.

### EZWinPorts — оставшийся кандидат

Манифест ScoopInstaller/Main указывает на архив:
https://downloads.sourceforge.net/project/ezwinports/make-4.4.1-without-guile-w32-bin.zip

Манифест:
https://github.com/ScoopInstaller/Main/blob/master/bucket/make.json

В нём указан SHA-1 **ZIP-архива**:
`f5d9f5450536bfb6dc11c5053cd36ba3699aafa5`.
Это не SHA-256 EXE пользователя и не подтверждение совпадения.

Попытки скачать ZIP с downloads.sourceforge.net, master.dl.sourceforge.net,
netix, phoenixnap и pilotfiber завершились TLS/сетевыми ошибками среды.
Поэтому размер и SHA-256 содержащегося там bin/make.exe не проверены.
Следующий шаг — скачать этот ZIP в отдельную временную папку (не поверх
рабочего toolchain), распаковать и сравнить SHA-256 bin/make.exe с эталоном.
Запускать EXE для сравнения не требуется.

## Вывод

TinyUSB: неизвестность существенно сужена до конкретного commit-кандидата с
совпадением двух полных файлов и точного времени. Make: один известный набор
готовых EXE исключён, ещё один источник требует скачивания и проверки хеша.
Никакие файлы прошивки, boot2 или внешние компоненты не заменялись.
