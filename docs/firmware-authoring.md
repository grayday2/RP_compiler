# Работа с кодом устройства (прошивка)

Это руководство для правок прошивки вокруг готового компилятора: как
добавлять макросы по-простому, как проверять, что они реально печатают,
секция паролей, шрифт и страницы OLED, и почему CMakeLists править не надо.

Прошивка — `main.cpp` в корне **приватной** рабочей копии. Публичный
репозиторий содержит плейсхолдер; реальный main.cpp и сгенерированные
секреты в него не коммитятся.

## Устройство

RP2040-Zero: USB HID-клавиатура (TinyUSB, device-only, один HID-интерфейс)
+ SSD1306 OLED 128x64 (I2C 0x3C, 400 кГц) + поворотный энкодер.

| Нога | Назначение |
|---|---|
| GP4, GP5 | I2C (SCL, SDA) — OLED, pull-up |
| GP6, GP7 | энкодер A/B (pull-up, прерывания по фронту) |
| GP8 | кнопка энкодера: коротко = выбор, долго (>=800 мс) = выход на уровень групп |
| GP11 | LED (включён при старте) |

Разделители энкодера: 4 такта = один шаг (ENC_DIVIDER). Драйвер OLED:
`libraries/ssd1306/` (framebuffer 128x64, page-mode, `ssd1306_draw_string`).

## Структура прошивки

```
группы groups[] = {CMD, SUPPORT, AUTH, KEYBOARD}
  └─ элементы Item {name, action, mode, data, len}
       └─ data = packed-массив (байт: старший бит = Shift, младшие 7 = HID-код)
страницы клавиатуры keyboard_pages[] = {LOWER, DIGITS, SYMBOLS, COMBOS, NANO, FUNC1, FUNC2}
  └─ KeyEntry {name, packed, modifier, keycode}
```

Печать: `send_packed()` ходит по массиву, каждый байт → report
(modifier|key), задержки 4 мс + 16 мс. Действия (enum Action): `A_TEXT`
(Ctrl+A + текст), `A_CMD` (текст + Enter), спец-действия (TECH/SUDO/NET/VID/
SERIAL/REBOOT/ENERGY/AUTH_*) — фиксированные последовательности.

## Как добавить текстовый макрос

### Способ A — простой (рекомендуется): таблица + make_macros.py

В приватной копии заведите таблицу (пример — `examples/macros_example.txt`
в репозитории):

```
# ИМЯ|ДЕЙСТВИЕ|ТЕКСТ   (имя A-Z/0-9/_ 2..16, текст — обычное слово по-русски)
MYSUPPORT|text|Требуется настройка рабочей станции, прошу передать на 2 ЛП.
MYCMD|cmd|sudo systemctl status
```

Запуск (бандл-Python, офлайн):

```bat
python scripts\make_macros.py my_macros.txt > my_macros_gen.h
```

Скрипт печатает готовые `static const uint8_t`-массивы (те же packed-байты,
что и вручную через ru_keys.h) и записи `Item` для вставки в main.cpp.
Неизвестный символ = ошибка с указанием строки и позиции. В main.cpp:
вставьте код и добавьте группу в `groups[]`: `{"MYGROUP", my_items, N}`.

Кириллица кодируется по русской раскладке на US-клавиатуре (а=F, б=, и т.д.
— ровно те же физические клавиши, что в `ru_keys.h`), латиница/цифры/знаки —
по US. То есть написание «со» даст буквы с-о на физических C-с… — то есть
то, что напечатает русская раскладка.

### Способ B — вручную, токенами ru_keys.h

Классика: массив из токенов (RU_A, RU_T_CAP, DIG_2, SYM_SPACE, LAT_X_CAP,
SYM_EXCL…). Полный список и физический смысл каждого токена — в
`libraries/ru_keys/ru_keys.h`. Правила:

- имя макроса на OLED: до 15 символов (вертикальные списки) или до ширины
  ячейки (сетки); имя показывается пользователю — пишите его латиницей;
- действия: `text` = A_TEXT, `cmd` = A_CMD (A_TEXT_PLAIN, если нужен «только
  текст», добавьте в enum Action и switch в run_item).

### Клавиши и комбинации (страница KEYBOARD)

`KeyEntry {имя, packed, modifier, keycode}`:
- обычная клавиша: имя — символ, packed = её packed-код (например `"a", LAT_A, 0, 0`);
- комбинация: `"Ctrl+C", 0, KEYBOARD_MODIFIER_LEFTCTRL, HID_KEY_C`;
- служебные: `"Enter", 0, 0, HID_KEY_ENTER`.

Проверка «имя ↔ код» для всех записей — в аудите (ниже); это и есть
защита от «ошибок в расположении клавиш».

## Проверка: audit_device.py

```bat
python scripts\audit_device.py
:: или с явными путями:
python scripts\audit_device.py path\to\main.cpp libraries\ru_keys\ru_keys.h
```

Что проверяет:

1. **ru_keys.h против эталонной русской раскладки**: все 33+33 буквы,
   RU_COMMA/RU_DOT, дубли packed-байтов;
2. **все packed-массивы**: каждый байт — валидный HID-код;
3. **декод каждого массива** — что реально напечатает (RU_* — по русской
   раскладке, LAT_/SYM_/DIG_ — по US). Секретные массивы (имена с pw/pass/
   login/secret) не расшифровываются;
4. **группы**: count в groups[] == реальной длине массива;
5. **страницы KEYBOARD**: каждая запись «имя ↔ сканкод» (117 записей);
6. **OLED 128x64**: влезание и наезжание для текущего шрифта 8x8 и кандидата
   8x12 (сетки, вертикальные списки, show_text, подчёркивание, CAPS ON).

Код возврата: 0 = чисто, 1 = есть FAIL, 2 = только WARN.

### Результаты аудита текущей прошивки (2026-09-16)

- Сканкоды: **все верны** (66 русских букв, 117 записей страниц, 2010 байтов
  массивов) — «ошибки расположения клавиш» в текущей версии не найдены.
- **Нашлось 1 дисплейный баг:** на странице FUNC2 имя `Enter` (5 символов =
  40px) не влезает в ячейку 32px и наезжает на `Caps`. Лечится переименованием
  в `Ent` (или `Cr`) — либо переделкой сетки FUNC2 в 2 колонки.
- **Нашлись опечатки в текстах** (и есть причина, почему «слова забавно
  багались»): аудит показывает, что каждый макрос реально печатает, например
  во всех SUPPORT-фразах «сер**и**йный недоступен» вместо «сер**в**исный
  недоступен» (в массивах стоит RU_I там, где нужен RU_V), «Альт**л**инукс»,
  «переустановк**усного** ПО». Список всех расшифрованных фраз даёт сам аудит
  — прогоните после каждой правки текстов.

## Секция паролей (make_secrets.py + secret_store.h)

Пароли/логины больше не надо писать токами RU_* вручную:

```bat
:: 1) получить код (в консоли, результат не сохранять в репозиторий):
python scripts\make_secrets.py --name auth_pw_login --text "ПАРОЛЬ_ЗДЕСЬ"
:: фиксированная соль (повторяемость) — опционально:
python scripts\make_secrets.py --name vidreg_pass --text "..." --salt 0x11223344
:: из файла (первая строка), раскладка US:
python scripts\make_secrets.py --name some_pw --file pw.txt --layout us
```

Скрипт печатает готовый C-код: соль + обфусцированный массив. В main.cpp:

```c
#include "secrets/secret_store.h"
...
uint8_t buf[256];
int n = secret_decode(auth_pw_login_salt, auth_pw_login_enc,
                      (int)sizeof(auth_pw_login_enc), buf, (int)sizeof(buf));
if (n > 0) { send_packed(buf, n); memset(buf, 0, sizeof(buf)); }
```

Схема: XOR со стримом splitmix32, затравленным солью. Декод в RAM в момент
ввода (сотни байт — единицы микросекунд на 133 МГц), буфер затирается.
Это обфускация, а не шифрование: защищает от случайного чтения бинарника,
не от целенаправленного анализа. Поэтому правило не меняется: если пароль
скомпрометирован — меняем пароль.

Контракт Python↔C зафиксирован тестом `tests/test_secrets.py` (золотой
вектор); если правите secret_store.h — прогоните тесты (при наличии g++
тест дополнительно компилирует заголовок).

## Шрифт и страницы OLED

- Текущий шрифт: 8x8 ASCII (95 глифов, `ssd1306_font.h`, колонка = байт,
  LSB = верх). Ветка шрифта на 8px — жёсткий предел: сетка LOWER 16
  колонок = ровно 8px на символ, расширять вширь нельзя.
- Доступен более высокий шрифт **8x12** (тот же рисунок, растянут по
  высоте): `libraries/ssd1306/ssd1306_font_8x12.h/.c`, функция
  `ssd1306_draw_string_big(x, y, str)`. Подхватывается CMake автоматически
  (новый .c в библиотеке — правок не нужно).
- Влезание при 8x12 (проверяется аудитем): сетки и вертикальные списки
  влезают по высоте ровно (шаг строки 12 = высота глифа, 4 строки =
  16..63), но:
  - подчёркивание-курсор на `y+9` пересечёт глиф — перенесите маркер
    (например, точка/полоска слева от строки);
  - строка «CAPS ON» на `y=8` наедет на заголовок высотой 12 — перенесите
    индикатор (например, справа от заголовка на той же строке).
- show_text (группа + item) в 8x12 влезает без изменений (строки y=0 и y=16).
- Имена строк: латиница/ASCII (шрифт ASCII-only; кириллица на OLED не
  отображается и сейчас — это не регресс).

## Почему CMakeLists.txt переписывать не нужно

`libraries/` — авто-собираемое:

- `file(GLOB ALL_LIBS LIST_DIRECTORIES true "${LIB_DIR}/*")` + foreach —
  каждый подкаталог `libraries/<имя>/` подключается как библиотека;
- внутри: `GLOB_RECURSE *.c *.cpp *.S *.s CONFIGURE_DEPENDS`
  (исключения: examples/tests/docs/build/.git) + include-пути `include/`,
  `src/` у каждой библиотеки;
- **и главное**: `build_firmware.py` полностью удаляет `build/` перед
  КАЖДЫМ configure — поэтому новый подкаталог надёжно перечитывается при
  любой сборке, даже без CONFIGURE_DEPENDS на внешнем GLOB.

Добавить библиотеку = создать папку `libraries/<имя>/` с файлами
(заголовок + исходник, опционально include/, src/) — и всё. Эти инварианты
зафиксированы тестом `tests/test_build_layout.py`.

Из текущих библиотек: `ru_keys` (header-only, токен-макросы), `ssd1306`
(драйвер + шрифты 8x8/8x12), `secrets` (header-only, обфускация).
`raspberry26x32.h` — мёртвый растр (26x32), нигде не включается; можно
удалить или использовать в заставке.

## Порядок работы (рекомендация)

1. Правка только одного дела (макрос ИЛИ страница ИЛИ шрифт) — не несколько.
2. `python scripts\audit_device.py` — до и после (декод фраз, наезжания).
3. `python -m unittest discover -s tests -v` + `compile.bat`.
4. Проверка на плате (BOOTSEL → firmware.uf2). Не подошло — вернуть
   последнее изменение, а не копить обходные правки.
