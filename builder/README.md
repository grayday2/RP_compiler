# Билдер прошивки сервисной клавиатуры (RP2040)

Билдер собирает готовый к компиляции `main.cpp` для устройства
«сервисная клавиатура» (RP2040 + OLED SSD1306 + поворотный энкодер,
прошивка изображает USB-клавиатуру через TinyUSB).

Логика работы такая:

* **данные** (пароли, фразы поддержки) живут в текстовых конфигах
  `data\*.txt` и редактируются через интерактивные меню;
* **код** разбит на независимые фрагменты `src\*.inc`;
* пункт меню **BUILD** склеивает фрагменты и сгенерированные секции
  в единый `out\main.cpp`, который остаётся только скомпилировать
  в вашем проекте Pico SDK.

---

## Запуск и меню

```
START.bat  (из корня репозитория)   или   builder\BUILDER.bat
```

Билдер сам выставляет кодовую страницу `866`. Главное меню:

| Пункт | Модуль | Назначение |
|---|---|---|
| 1 | `modules\auth.bat` | пароли: добавить / просмотр / удалить |
| 2 | `modules\support.bat` | фразы поддержки: добавить / просмотр / удалить |
| 3 | `modules\macros.bat` | модуль макросов CMD (просмотр, правка вручную) |
| 4 | `modules\keyboard.bat` | модуль клавиатуры (просмотр, правка вручную) |
| 5 | `modules\build.bat` | сборка `out\main.cpp` |

Модульность: `BUILDER.bat` — только меню и диспетчеризация, всю работу
делают вызываемые через `call` модули и библиотеки `lib\*.bat`.

## Порядок сборки (что во что склеивается)

`modules\build.bat` собирает `out\main.cpp` в таком порядке:

| № | Файл | Откуда |
|---|---|---|
| 1 | `src\00_header.inc` | статический |
| 2 | `tmp\gen_support.inc` | генерируется из `data\support.txt` |
| 3 | `src\20_macros.inc` | статический (правится вручную) |
| 4 | `tmp\gen_auth.inc` | генерируется из `data\auth.txt` |
| 5 | `src\40_keyboard.inc` | статический |
| 6 | `tmp\gen_groups.inc` | генерируется (список групп, счётчики через `sizeof`) |
| 7 | `src\50_engine.inc` | статический |
| 8 | `src\60_keyboard_ui.inc` | статический |
| 9 | `src\70_main.inc` | статический |

Секции, которые генерирует билдер:

* **SUPPORT**: на каждую фразу — массив `sup_ИМЯ[]` из токенов и строка в
  `support_items[]` с действием `A_TEXT` (Ctrl+A «выделить всё» и печать
  фразы);
* **AUTH**: на каждый пароль — массив `auth_ИМЯ[]` и строка в `auth_items[]`
  с действием `A_SEND` — **просто послать клавиши, без Enter и без
  побочных макросов**;
* **группы**: `groups[] = { CMD, SUPPORT, AUTH, KEYBOARD }`; количество
  пунктов считается через `sizeof`, поэтому при правке макросов счётчики
  вручную обновлять не нужно. Клавиатура всегда последняя (индекс 3 —
  на это завязана логика в `70_main.inc`).

## Форматы конфигов

### `data\auth.txt` — пароли

```
ИМЯ|ТОКЕНЫ
```

* `ИМЯ` — отображаемое имя в меню устройства: латинские буквы, цифры,
  пробел, `-`, `_`; не более 15 символов;
* `ТОКЕНЫ` — последовательность клавиш через запятую: `LAT_*` (латиница,
  заглавные — `LAT_X_CAP`), `DIG_0..DIG_9`, `SYM_*` (см. справочник ниже).

Пример: `MY_PW|LAT_Q,LAT_W,DIG_1,DIG_2,DIG_3`

Добавление через меню: билдер спрашивает пароль, затем отображаемое имя
(можно добавить несколько подряд и вернуться в меню), сразу переводит
пароль в токены и дописывает строку. Удаление — по номеру из списка.

### `data\support.txt` — фразы

```
ИМЯ|ТОКЕНЫ|ТЕКСТ
```

* `ИМЯ` — как в `auth.txt`;
* `ТОКЕНЫ` — `RU_*` (русские буквы, заглавные — `_CAP`), `DIG_*`,
  `RU_SPACE`, `RU_COMMA`, `RU_DOT` и `SYM_*` для `- : ! ?`;
* `ТЕКСТ` — человекочитаемый вид фразы; при сборке не используется,
  нужен только для просмотра.

Добавление через меню: билдер спрашивает имя и фразу на русском, сам
переводит её в токены. Строки, начинающиеся с `;`, считаются
комментариями и при сборке пропускаются.

## МАКРОСЫ (группа CMD) — как редактировать

Пока редактирование **вручную** в `src\20_macros.inc` (билдер открывает
его блокнотом, меню 3 → V):

1. каждая макроса — массив токенов:
   ```c
   static const uint8_t moja_cmd[] = { LAT_S,LAT_U,LAT_D,LAT_O,SYM_SPACE,... };
   ```
2. добавьте строку в `cmd_items[]`:
   ```c
   {"ИМЯ В МЕНЮ", A_CMD, SIMPLE, moja_cmd, sizeof(moja_cmd)},
   ```
3. действия: `A_CMD` — напечатать и нажать Enter; особые сценарии
   `A_TECH / A_SUDO / A_NET / A_VID / A_SERIAL / A_REBOOT / A_ENERGY`
   реализованы функциями `do_tech()/do_sudo()/...` в `50_engine.inc` —
   новый сценарий добавляется там же (функция + строка в `switch`
   `run_item()` + значение в `enum Action` в `00_header.inc`);
4. счётчик пунктов править не нужно — он считается через `sizeof`.

## КЛАВИАТУРА — как редактировать

Данные экранной клавиатуры — `src\40_keyboard.inc` (меню 4 → V):

* клавиша — строка `{"имя", packed, modifier, keycode}`:
  либо токен из `ru_keys.h` в `packed` (тогда `modifier=0, keycode=0`),
  либо HID-код в `keycode` с модификатором в `modifier`;
* страницы: `LOWER / DIGITS / SYMBOLS / COMBOS / NANO / FUNC1 / FUNC2`,
  сводятся в таблицу `keyboard_pages[]`;
* **важно**: третье число в `keyboard_pages[]` — размер массива страницы,
  при добавлении/удалении клавиш обновляйте его;
* отрисовка и навигация — `src\60_keyboard_ui.inc` (меню 4 → U).

## СПРАВОЧНИК ТОКЕНОВ

Токены — это константы из `ru_keys.h` вашего проекта прошивки
(по смыслу — HID-коды клавиш с учётом русской раскладки).

**Латиница**: `LAT_A..LAT_Z` (строчные), `LAT_A_CAP..LAT_Z_CAP`
(заглавные, с Shift).

**Цифры**: `DIG_0..DIG_9`.

**Символы**:

| Токен | Символ | Токен | Символ | Токен | Символ |
|---|---|---|---|---|---|
| `SYM_SPACE` | пробел | `SYM_UNDER` | `_` | `SYM_PIPE` | `\|` |
| `SYM_EXCL` | `!` | `SYM_EQUAL` | `=` | `SYM_SEMI` | `;` |
| `SYM_AT` | `@` | `SYM_PLUS` | `+` | `SYM_COLON` | `:` |
| `SYM_HASH` | `#` | `SYM_LBRACK` | `[` | `SYM_SQUOTE` | `'` |
| `SYM_DOLLAR` | `$` | `SYM_RBRACK` | `]` | `SYM_DQUOTE` | `"` |
| `SYM_PERCENT` | `%` | `SYM_LBRACE` | `{` | `SYM_COMMA` | `,` |
| `SYM_CARET` | `^` | `SYM_RBRACE` | `}` | `SYM_LT` / `SYM_GT` | `<` / `>` |
| `SYM_AMP` | `&` | `SYM_BSLASH` | `\` | `SYM_DOT` | `.` |
| `SYM_STAR` | `*` | `SYM_MINUS` | `-` | `SYM_SLASH` / `SYM_QMARK` | `/` / `?` |
| `SYM_LPAREN` / `SYM_RPAREN` | `(` / `)` | | | `SYM_TILDE` | `~` |

**Русские буквы** (строчная / прописная):

| Буква | Токен | Буква | Токен | Буква | Токен |
|---|---|---|---|---|---|
| а/А | `RU_A` / `RU_A_CAP` | к/К | `RU_K`(_CAP) | х/Х | `RU_KH`(_CAP) |
| б/Б | `RU_B`(_CAP) | л/Л | `RU_L`(_CAP) | ц/Ц | `RU_TS`(_CAP) |
| в/В | `RU_V`(_CAP) | м/М | `RU_M`(_CAP) | ч/Ч | `RU_CH`(_CAP) |
| г/Г | `RU_G`(_CAP) | н/Н | `RU_N`(_CAP) | ш/Ш | `RU_SH`(_CAP) |
| д/Д | `RU_D`(_CAP) | о/О | `RU_O`(_CAP) | щ/Щ | `RU_SHCH`(_CAP) |
| е/Е, э/Э | `RU_E`(_CAP) | п/П | `RU_P`(_CAP) | ъ/Ъ | `RU_HARD`(_CAP) |
| ё/Ё | `RU_YO`(_CAP) | р/Р | `RU_R`(_CAP) | ы/Ы | `RU_YI`(_CAP) |
| ж/Ж | `RU_ZH`(_CAP) | с/С | `RU_S`(_CAP) | ь/Ь | `RU_SOFT`(_CAP) |
| з/З | `RU_Z`(_CAP) | т/Т | `RU_T`(_CAP) | ю/Ю | `RU_YU`(_CAP) |
| и/И | `RU_I`(_CAP) | у/У | `RU_U`(_CAP) | я/Я | `RU_YA`(_CAP) |
| й/Й | `RU_Y`(_CAP) | ф/Ф | `RU_F`(_CAP) | | |

Пробел/запятая/точка в русском тексте: `RU_SPACE`, `RU_COMMA`,
`RU_DOT`; знаки `- : ! ?` — соответствующие `SYM_*`.

**Замечания по токенм** (важно при первой компиляции):

* в оригинальной прошивке `э/Э` печаталась токеном `RU_E(_CAP)` — так же
  делает и билдер;
* токены `RU_YO`, `RU_HARD`, `RU_SHCH` в оригинале не использовались и
  добавлены билдером по тому же принципу именования: проверьте их
  наличие в вашем `ru_keys.h` (если их нет — либо добавьте, либо не
  используйте соответствующие буквы во фразах);
* `send_packed()` применяет Shift, если у токена установлен бит `0x80`
  (это зона ответственности определений в `ru_keys.h`).

## Кодировки (важно!)

* Интерактивные `.bat`-файлы и конфиги с русским текстом должны быть в
  **CP866 (OEM)** с концами строк **CRLF** — иначе cmd.exe не поймёт
  кириллицу. Рабочие файлы уже в таком виде.
* Если нужно править `.bat`: правьте UTF-8-исходник в `builder\.masters\`
  и запускайте `python builder\tools\sync_encoding.py` — он пересоберёт
  рабочие файлы в CP866. Запуск билдера от Python не зависит.
* Консоль: билдер сам выполняет `chcp 866`. Русские фразы вводятся в
  консоли как обычно (русская раскладка).
* Если редактируете `data\*.txt` вручную в блокноте — токены (поля до
  второго `|`) чисто ASCII и переживают любую кодировку; текстовое поле
  фразы при ручной правке можно не трогать.

## Ограничения (осознанные, «для макета»)

* `set /p` не умеет скрывать ввод — пароль при добавлении виден на экране;
* имена пунктов — латиница, до 15 символов (ширина строки OLED);
* в фразах поддержки допускаются русские буквы, цифры, пробел и
  `, . - : ! ?` — прочие символы билдер отклонит с подсказкой;
* интерактивного редактора макросов и клавиатуры пока нет — они лежат
  готовыми C-фрагментами и правятся вручную (формат описан выше и в
  шапках самих фрагментов).

## Компиляция результата

`builder\out\main.cpp` — обычный C++-файл прошивки. Положите его в ваш
проект вместо старого `main.cpp` и соберите штатно
(`pico-sdk` + `tinyusb`, заголовки `ssd1306_i2c.h` и `ru_keys.h` должны
быть в проекте). В собранном виде файл должен совпадать по поведению со
старой прошивкой: группы меню CMD / SUPPORT / AUTH / KEYBOARD,
энкодер — выбор, короткое нажатие — выполнить, длинное — назад к группам.

## Безопасность

Файлы с реальными данными исключены из git (см. корневой `.gitignore`):
`data\auth.txt`, `data\support.txt`, `src\20_macros.inc`, `out\`, `tmp\`.
В репозитории лежат только `*.example`-шаблоны. Не публикуйте эти файлы
и не вставляйте их содержимое в переписку/тикеты.
